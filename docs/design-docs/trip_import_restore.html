Design study · data from the Madagascar round trip, numbers illustrative

Bring a trip home mockup

Moving a trip from one computer to another: the trip itself, its metadata from the SV INDEX card, and its pictures from the SD-cards and dumps. One window, three numbered steps, each with its own status. Steps 2 and 3 work in either order and can be repeated.

What was agreed (13 Nov 2026)
  • Import Trip is the entry point, and the other two steps grow out of it.
  • "Restore work from a card" becomes Read metadata from SV INDEX card.
  • The newer copy wins. When this computer's copy is newer it is kept and only counted, never offered for overwriting. When the card's copy is newer it is taken by default, and you confirm once per day.
  • Reading cards and dumps keeps your own choice of days, and scanning starts when the window opens.
  • Sources can differ: the SV INDEX card can hold 6 days while a dump holds 7. Nothing assumes they agree.
  • The metadata backup and the RAW backup follow the same folder rule, so the default always works.

Rules behind the columns

  • New: the file is not here. It is always written.
  • Newer on the card: the content differs and the card's date is later. It is written; the copy here goes to the day's .trash first.
  • Newer here: the content differs and this computer's date is later. It is never overwritten, only counted. A day where every difference is "newer here" starts unticked (2026-11-02 above).
  • Same: same size and content. It is skipped. Dates are compared with 2 seconds of slack, because the card's file system stores time in 2-second steps.
  • Details of a day… lists the files behind the numbers, read-only, for the one day you want to inspect. That is where you look before ticking, instead of answering a question per file.
  • A day that exists here but not on the card (2026-11-10) is shown dimmed, so it is clear the card is incomplete rather than that the day was lost.

  • Prefix: the check is not case-sensitive, so 2026 madagascar - HOQM5401.JPG is recognised as already prefixed with "2026 Madagascar". A double prefix becomes impossible from this window.
  • Metadata on a card or dump follows the same newer-wins rule as step 2. A dump made later than the SV INDEX backup brings its newer XMPs; an older one changes nothing.
  • Opened from the menu outside a trip import, the window behaves as it does today: the fields are unlocked and nothing is filled in from a backup.
  • After a read, step 2's counts are recalculated against the card's last plan, so you can see whether reading the SV INDEX card again would still change anything. The answer is visible, not guessed.

Screen 4 — the folder rule for both backups

Both backups lay the card out the same way. You choose the card or drive, and SV adds the trip folder itself.

H:\ ← what you choose (SV INDEX card) 2026 Madagascar\ ← SV adds the trip folder madagascardb.zip metadata · the trip 2026 Madagascar - 2026-10-28.zip metadata · one per day … tracklogs\ settings\ metadata 2026-10-28\ RAW backup · one folder per day … 2026 Madagascar\2026 Madagascar\ ← what happened: the trip folder was chosen as the card
Back up the day's work✕

H:\2026 Madagascar is a trip folder on the SV INDEX card, not the card itself.

The backup always adds the trip's own folder, so choosing a trip folder would put a second "2026 Madagascar" inside it. SV will use H:\ instead, the same place as the other trips on this card.

Use H:\Choose another folder…
  • A trip folder is recognised by its contents (a trip ZIP, day ZIPs or day folders), not by its name.
  • The same check applies to the RAW backup's folder and to the SV INDEX folder in step 2. Reading also finds backups that are already one level too deep (Goeree, North Greece, Madagascar), so those cards work without moving anything.
  • The two backups keep separate folder settings. The RAW backup may go to a bigger disk, but when both point at the same card the layout above is what you get. Before a RAW backup onto the SV INDEX card, SV checks the free space and keeps enough room for the next metadata backup.

Open questions

1. The menu item. Should Read metadata from SV INDEX card… stay as its own menu item, opening this window at step 2? I recommend yes: after a trip, during it, or on the same computer, you would otherwise have to go through Import.
2. Step 2 without the card inserted. With several card readers the SV INDEX card can stay in, but if it is taken out, step 2 would show "the card is not inserted" with the last counts greyed out. Do you agree, or should step 2 keep a copy of the day list on this computer? I recommend the first: no extra copies, and the message says what to do.
3. The window's name. "Import Trip" now does three things. Keep the name "Import Trip" (familiar, and it is the menu item), or call the window "Bring a trip home"? I recommend keeping "Import Trip", with the trip's name after it in the title.
