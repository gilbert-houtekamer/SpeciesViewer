> **Body names are the camera's own.** These are the `Model` strings the cameras write into their files, not marketing names — so the Z 7II calls itself `NIKON Z 7_2`, the Z 50II `NIKON Z50_2`, and the R5 Mark II `Canon EOS R5m2`. They are left exactly as the file reports them, because that is the string SpeciesViewer sees, and a translation table would be one more hand-typed list to drift.

## What the columns mean

A RAW passes through five independent mechanisms, and a body can fail at one while working at the other four. That is why this is a table and not a yes/no.

| Column | Question | What a ❌ costs you |
|---|---|---|
| **Date** | Does `DateTimeOriginal` read? | Nothing works. Pictures are filed by day. |
| **Sidecar** | Does an XMP sidecar get written, carrying the date? | Ratings, colour labels and GPS have nowhere to live. |
| **Focus dist.** | Does a focus distance reach the picture's fields? | The distance line is blank on the website and in the info panel. Nothing else depends on it. |
| **Preview** | Does a *usable* preview come out — a real JPEG, not merely some embed? | Culling falls back to a full decode: still correct, roughly 30× slower. |
| **Decode** | Does LibRaw decode the sensor data? | The 100% view and Create JPG fall back to the embedded JPEG. DxO PhotoLab is unaffected — it does its own decoding. |

**No single ❌ above means "unsupported".** Each column has a fallback, and the fallbacks are independent — which is the whole reason for measuring them separately. A body with a red Preview and a green Decode still culls correctly, just slower; a body with a green Preview and a red Decode still shows every picture at full size, because the camera's own JPEG is in the file.

## Known gaps

**Focus distance is missing on Panasonic** (1 of the 20 rows here) — because those files do not contain it, not because nothing asks. Every maker keeps it somewhere different, and `engine/focus_distance.py` merges all four shapes into the single value the website and the info panel read:

| Maker | Where the file keeps it | Read |
|---|---|:-:|
| Nikon | `Nikon:FocusDistance` — a single value | ✅ |
| Olympus / OM System | `Olympus:FocusDistance` — a single value | ✅ |
| Sony | `Composite:FocusDistance2` — derived by exiftool | ✅ |
| Canon | `FocusDistanceUpper` / `Lower` — a **range**, no single value | ✅ averaged |
| Panasonic | nothing. Only `HyperfocalDistance`, which is a property of the lens and aperture, not of what the camera focused on | — |

Canon's two bounds are averaged. The true subject distance is not quite the midpoint — depth of field is asymmetric about the plane of focus, so it sits slightly nearer — but the bounds are centimetres apart at the distances that matter, and a simple number that can be checked beats a formula that cannot.

Panasonic is the one genuine absence: there is nothing in the file to read. Reporting `HyperfocalDistance` instead would fill the field with a number that answers a different question.

> The XMP sidecar written at ingest is narrower than any of this — it maps only `Olympus:FocusDistance`. That does not show up in this column, because the website and the info panels read the master scan's fields rather than the sidecar.
