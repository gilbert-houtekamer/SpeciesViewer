Shipped — the retroactive trip (Sri Lanka is live)

  • WP7 — scenario-2 “retroactive” pipeline SHIPPED — a virtual trip for a journey that never had a SpeciesViewer trip now runs end-to-end: Sri Lanka 2018-11-17 → 12-07, 1766 pictures, 148 species, 21 days — created, blogged, mapped and published. The blocker was not missing code. The auto-blog writer (day title from the day's locations, opening sentence, species callouts) was complete but had been unplugged: the day loop said “never fabricate blog text — a day gets a page only if it already has a blog ini.” That is right for a retired trip, whose blogs are migrated from the real trip, but it meant a retroactive trip — which has no source trip and nothing to migrate — skipped every day and then failed outright. The blog editor was no escape either: it only opens tabs for blogs that already exist, so you got an empty dialog. Auto-create is now back, behind a gate.
  • The gate is “this trip has no blogs at all”, not “no source trip” SHIPPED — the obvious rule (auto-create when source_trip_id is empty) would have been a bug: every virtual trip made before that key existed carries an empty one, gaps and all — safari has 28 blogs across 30 days, costa-rica 23 of 25, gambia 26 of 29. Keying off it would have fabricated drafts into exactly the deliberate gaps the original block existed to protect. Checked against all eleven virtual trips on disk: ten default off, only Sri Lanka on. A checkbox in Write Blogs overrides it either way.
  • Amber / green blog-review bubbles SHIPPED — the same piece of work: auto-generation was disabled because it fabricated silently, and amber/green is what makes it visible — so it is what earns back the right to generate at all. A day blog is now 🟠 draft (written automatically, nobody has read it) or 🟢 reviewed (your words), with the count in the trip header. In the editor a draft page carries an amber banner and a Reviewed checkbox — and editing the text counts as reviewing it, so Save All deliberately does not bless every draft at once, which would make the flag meaningless. Old hand-written blogs stay green; a blog left by the old auto-writer is still recognised (by its marker) and correctly shows amber.
  • Single-day blog re-upload SHIPPED (was parked as “future”) — “Save & Upload this day” on each editor page republishes only that day. The trap: the blog step opens every run by clearing the blog index so stale entries vanish — doing that for a single day would have dropped the other twenty out of the index and orphaned their live pages. Single-day mode skips the wipe and updates just that day in place.
  • Geotag the master from the virtual-trip map SHIPPED — the map was flatly read-only because a virtual trip's files are the master's — which also made it the best surface we have for fixing the master's missing coordinates. Geotagging is now let through, and only geotagging: rating, colour, crop and delete stay refused, and the permission is gated on the machine's existing master write policy, so a read-only master still gets the view-only map. Two rules hold it honest. Fill, never overwrite: you can place a picture that has no coordinate, but you cannot drag a bubble to move pictures whose coordinates the camera recorded. And the map says what it does — where it read “· view only” it now reads “· placing writes to the master”.
    To see where the work is, each day now shows a No GPS count; double-click it to open that day's map. Sri Lanka: 285 of 2060 pictures, with two days consisting of nothing but those — which is precisely why they auto-titled “onbekend”.
  • GPS provenance — telling our coordinates from the camera's SHIPPED — needed before any batch can seed coordinates from a place name, because a seeded picture has GPS and would otherwise be frozen: moving it is exactly what the map forbids. The idea of marking a derived coordinate by making it less precise (whole arcseconds) was tested against the master and 791 of 41,246 GPS'd pictures (1.9%) already look like that — Galapagos 2015 repeating one coordinate across many photos, a South Africa shot at a suspiciously round position. The instinct was right that something is there, but as a permission signal it fails, and it rides on a number that any tool may reformat. So the idea was split into its two true jobs:
    Permission now lives in GPSProcessingMethod, the field whose actual purpose is recording how a fix was obtained. Blank means the camera measured it and we do not touch it; “manual” means a person placed it, so it may be moved and refined.
    Precision is about telling the truth: a place-name look-up is accurate to tens of metres, so its coordinate is rounded to match — and it visibly reads as approximate (47.00" beside a camera's 46.52"), which is the cue that it still wants attention. It never decides what you are allowed to do.
    The map's rule therefore sharpens from “fill, never overwrite” to “never overwrite what we did not put there ourselves”.
  • Find a place by name SHIPPED — we had OpenStreetMap look-up in one direction only (coordinates → place name). This adds the mirror: type “Jetwing St. Andrews, Nuwara Eliya” and get the coordinate. It sits in the right-click menu just after Suggest a position — for when the camera recorded nothing but you wrote the place down. It doesn't place the picture for you: it drops the same draggable pin, because the hotel's coordinate is where the hotel is, not where the bird was. The search prefers the part of the world already on your screen (St. Andrews is also in Scotland), and it will place a whole selection at once.
