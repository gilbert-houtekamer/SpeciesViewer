SpeciesViewer — Project Backlog

Updated: 11 July 2026 (Refresh Master Database + black-image fixes)  ·  Branch: ClaudeSpecies  ·  Author: Gilbert Houtekamer

Working task list for the SpeciesViewer nature-photo pipeline and GUI. Since the 16 June version most of the backlog has shipped: the identity/​picture-root decouple, the cross-platform path layer, the retire-to-virtual-trip arc, the Working Days lane, and the whole Trip Species Viewer delete rework are all done (see Recently Completed at the end). What remains is a short list — focus is on that.

Status legend: OPEN to build · NEW newly raised · BUG defect to fix · NEEDS TEST built, awaiting a live run · PARKED deliberately deferred (“not now, by choice”) · REJECTED decided against (won't build) · DONE shipped. Each chapter separates things to do from things that are parked by design.

11. Performance & EXIFtool

Done

  • EXIFtool parallel workers SHIPPED — cold day/master reads split the uncached files across N independent exiftool processes (exifcache.read_metadata_parallel + auto_worker_count = min(cpu//2, 16, files//24)); wired into sv2 Read Directory, master Rescan, and SD-card XMP creation. Speedup peaks at physical cores (BigBoy ≈7.4×; master rescan 159,973 files cold ~5m25s @16). Output byte-identical to serial. Config [performance] exif_workers = auto. (65e0c45)

To do

  • GBIF lookup disk-cache NEW OPEN — after the parallel EXIF read, species classification is the Read-Directory bottleneck (704 files read in 2.0 s, then GBIF dominates). GBIF results are cached only in memory for the run. Persist a subject-string → backbone cache to disk (incl. not-found), and/or write GBIF-resolved species back into speciescollection at session end, so lookups survive across sessions/machines. Caching beats parallelizing (external API + rate limits).
  • Shared persistent exiftool server OPEN — a per-operation -stay_open exiftool already exists (gui/preview_extract.py; sv2 reads). The idea is one app-wide server + worker pool rather than launching per run. Ties the paused micro-optimization notes: the real value is the write-contract + big reads, not per-item micro-perf.

Parked (by design)

  • PAUSED General micro-perf sweep — one processEvents throttle shipped; the rest was non-winning or bordered risky metadata paths. Revisit only with a measured bottleneck.
