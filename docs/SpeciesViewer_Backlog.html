SpeciesViewer — Project Backlog

Updated: 13 June 2026  ·  Branch: ClaudeSpecies  ·  Author: Gilbert Houtekamer

Working task list for the SpeciesViewer nature-photo pipeline and GUI. Items are grouped by feature area. Each section shows what is open, what has been shipped recently, and what is deliberately deferred.

1. SD-card Ingest & Culling

Milestones M0–M4 (copy, prefix, date-sort, validation, viewer), plus sidecar cache and GPS place-names, are all SHIPPED & TESTED.

Still open

  • M5 — Bulk species assignment in the grid NOT BUILT
    Marquee-select multiple picture cards, then stamp them all with one species keyword (type-ahead auto-complete, GBIF online fallback). The current workflow handles one picture at a time; this is the batch equivalent for day-wide or trip-wide assignment.
  • Cancel button during copy NEEDS LIVE TEST
    Shipped (commit e6f49a7): Close button becomes "Cancel" during a running copy; clicking it stops the worker. Has not yet been tested against a real SD-card copy run.

Deferred (GPS / geolocation fine-tuning)

  • Tune Nominatim zoom level so Location returns a reserve or lake name rather than the nearest road (current zoom 14 returns roads most of the time).
  • Expose lang / radius / zoom settings and an overwrite toggle in the UI.
  • Push the Municipality field into the pipeline CSV and website output (currently written to XMP only).
  • Offline reverse_geocoder (scipy) fallback for use without internet.
  • Cache the LOCATION read per navigation step if it turns out to be laggy.

2. Virtual Trips BIG FEATURE

The core infrastructure is working: create a virtual trip, populate per-day CSVs from the master, view pictures read-only. The main remaining work is publishing.

  • Write Blog for virtual trips — currently a disabled placeholder (white dot) in the virtual-trip overview. Needs a new batch module (svv3WriteBlog?) that generates blog text from the curated species list, reading from data_pictures.csv rather than the live master scan.
  • Build Website for virtual trips — also a placeholder. Needs the full web-build pipeline adapted for virtual trips.
  • Deferred: VirtTrip panel refresh after "Create Virtual Trip" (currently requires a restart to see the new trip in the list); web root update on trip switch.

3. Master Database & Editing

Phases 1–3 are SHIPPED & LIVE-TESTED: Phase 1 (SQLite read-cache), Phase 2 (DB-first re-rating with WAL + CSV checkpoint), Phase 3 (add / delete pictures with reversible file-move to trash). The Rating Editor's Trip+Master scope is fully working.

Still open

  • "Undo last delete" UI button — the headless capability (undo_delete()) is built and tested; it reads the trash manifest, moves files back, and restores the DB rows. No menu item or toolbar button exists yet.
  • EXIF-cache mutable bucket prune — the mutable bucket (XMP / JPG files keyed by path + mtime) grows without bound as master re-reads accumulate. Add a size-capped or time-based eviction pass.

Deferred

  • Trip-side SQLite DBs — same pattern as the master DB, not urgent now that the design is proven by the master implementation.

6. Taxonomy & Species

All four items are still pending:

  • Sequence redesign — replace the "040 passeriformes" text-prefix sort with an eBird TAXON_ORDER float column. Schema change touching the species tree and all sort / display logic.
  • Auto-detect obscure flag — derive from GBIF family membership (Orchidaceae, Orobanchaceae, etc.) using data already fetched during species lookup. No extra API call needed.
  • Placeholder-species cleanup — ? <name> entries are intentional placeholders that propagate from trip to master via merge. Cleaning them up requires coordinated changes in both trip and master collections.
  • Regional most-likely-birds list (eBird API) — weighted auto-complete for species assignment in the culling viewer. Deferred.

7. Rating & Website

  • Rating-formula tuning DEFERRED
    Fine-tuning the weights (Red/Yellow/Green boost, star / size / DxO / description balance) is deliberately deferred to the end of the viewer-convergence work. Tuning now risks wasting effort before the full picture set is finalised. This formula directly feeds the website best-pick selection.
  • HEIC / PNG sidecar capture NEEDS DECISION
    HEIC-only and PNG-only pictures have no writable sidecar, so rating and colour cannot be stored durably (controls are greyed in the UI today). Three options under consideration:
    • (a) Write a separate .xmp sidecar alongside the HEIC
    • (b) Patch the .dop DxO project file
    • (c) Write directly into the HEIC container
    User decision required before coding starts.

9. Usability & Polish

  • Virtual-trip preview path — needs live test
    FileListPreviewCollection and FilePreviewItem back the virtual-trip file_list mode and metadata-less day folders. Import-verified but not yet exercised in a running app — confirm thumbnails render and the filter buttons are greyed correctly.
  • Preview cards don't resize live
    Card width is fixed at build time and only recomputed when the column spinner changes (matches the Rating Editor's behaviour). If this feels wrong in daily use, add a debounced resizeEvent that rebuilds at the new card width.
  • Commit the config state files doc SMALL TASK
    docs/config_state_files.md has been written (covers machine / master / trip / per-day / per-card scopes, deletion safety table) but is currently untracked. Stage it and commit.
  • "Undo last delete" UI button — the headless capability is done (see item 3); surface it as a menu item or button in the Rating Editor or Database Settings dialog.
  • Watch point — Translation: when a source text is edited, its CRC changes and the old cache entry becomes an orphan. Not a crash, but stale entries accumulate. Also: if a HEIC ever holds a competing Headline/Description value, the pipeline could re-resolve to the HEIC's stale text after a re-read (not observed in testing; watch only).
  • Deferred: user-configurable cache locations (all currently in %LOCALAPPDATA%).

10. Cross-platform (Mac) Prep

First pass DONE (commit 8701821): open_path() helper that routes to the correct OS call; Windows-only defaults in dialogs cleared.

Full portability sweep still pending before the MacBook switch:

  • Remaining os.startfile() call sites — no equivalent on macOS.
  • Hardcoded paths containing drive letters (E:/Dropbox/…) or backslashes.
  • QSettings registry usage — macOS uses ~/Library/Preferences, not the Windows registry.
  • Case-sensitivity traps — file lookups that work on Windows (case-insensitive NTFS) but fail silently on macOS (case-sensitive HFS+), e.g. file.jpg vs file.JPG.
  • subprocess calls that assume Windows path conventions or Windows-only tools (exiftool.exe etc.).
