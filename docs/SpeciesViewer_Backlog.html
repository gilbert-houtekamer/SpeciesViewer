11. Performance & EXIFtool

To do

  • EXIFtool throughput NEW OPEN / investigate — two ideas to speed up the big directory reads:
    • Parallel workers — split a large read into N shards (e.g. 4 exiftool processes each on 1/4 of the files) and merge. Measure the real speedup vs I/O / Dropbox limits before committing.
    • Shared persistent server — a single long-lived -stay_open exiftool reused across operations. Note: a persistent stay_open exiftool already exists per-operation (preview extraction gui/preview_extract.py; sv2 reads via one stay_open process). The idea is to widen that to one app-wide server (and/or the N-worker pool) rather than launching per run.
    Ties the paused micro-optimization notes (project_perf_optimizations): the real value is the XMP/.dop/PhotoLab write-contract + big reads, not per-item micro-perf.

Parked (by design)

  • PAUSED General micro-perf sweep — one processEvents throttle shipped; the rest was non-winning or bordered risky metadata paths. Revisit only with a measured bottleneck.
